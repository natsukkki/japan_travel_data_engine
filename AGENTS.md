# Ориентиры для агента

## Назначение и способ работы

Это учебный портфолио-проект по Data Engineering. Пользователь хочет понимать решения и самостоятельно писать рабочий код. При обсуждении, диагностике и ревью сначала объясняй фактическое поведение и помогай найти следующий шаг; не переписывай рабочий код без прямой просьбы. Полную реализацию рабочего кода делай по прямому запросу, поясняя причины выбора, альтернативы и ограничения. Тесты пиши и поддерживай самостоятельно; если тест обнаружил ошибку в коде пользователя, объясни её до изменения рабочего кода.

При архитектурном выборе соотноси сложность с масштабом pet-проекта. Отделяй реализованное от плана, факты кода от рекомендаций. Не называй будущие сервисы работающими. Значимые изменения архитектуры сначала обсуждай с пользователем. Более подробные пользовательские предпочтения лежат в `../docs/пользовательские инструкции.txt` (это соседняя папка вне репозитория); если файл доступен, учитывай его.

## Где что находится

- `README.md` — текущий статус, схема будущей системы и локальный запуск.
- `ingestion/batch/` — четыре загрузчика: Open-Meteo, JTA tourism, e-Stat regional price index, JMA sakura.
- `ingestion/storage/minio.py` — общие операции записи и чтения MinIO.
- `ingestion/batch/config/regions.json` — восемь выбранных регионов и координаты.
- `processing/spark/load_regions.py` — загрузка справочника в PostgreSQL.
- `processing/spark/weather_etl.py` — единственный реализованный Spark ETL источника в DDS.
- `processing/spark/jdbc.py`, `config.py`, `session.py` — доступ к PostgreSQL и настройка Spark.
- `infrastructure/config/postgres/init/` — создаваемые при первом запуске volume схемы и таблицы.
- `infrastructure/docker/docker-compose.yml` — сейчас MinIO, PostgreSQL и Spark.
- `docs/weather-ingestion-recovery.md` — точные правила повтора погодной загрузки.
- `tests/` — unit-тесты и тесты Spark без записи в реальные MinIO и PostgreSQL.
- `../docs/архитектура-проекта.md` — отдельное описание архитектурных решений вне репозитория, если соседняя папка доступна.

## Инварианты и ограничения

- Сверяй описание с кодом: `dds_schema` и **`marts_schema`** создаются SQL-скриптом; dbt и витрины пока только запланированы.
- Batch raw-файлы хранятся в MinIO. Kafka, Airflow, dbt, Spark Structured Streaming и Streamlit пока не реализованы.
- Погодный ingestion хранит state по регионам в `state/openmeteo_weather.json`. Сначала пишет и проверяет raw-объект, затем подтверждает прогресс в state. Ключ нового файла зависит от региона и начальной даты диапазона; повтор может заменить содержимое того же ключа.
- Spark ETL выбирает погодные ключи, которых нет в `dds_weather_processed_files`. После проверок пишет staging, затем переносит строки в `dds_weather_daily`, регистрирует ключи и очищает staging в одной транзакции PostgreSQL. JDBC-запись staging не входит в эту транзакцию.
- Зерно погоды в DDS — `(region_id, weather_date)`; дубли дат и неизвестные регионы отклоняются. Автоматическое исправление ранее обработанного raw-объекта не реализовано.
- В текущем дизайне одновременно выполняется один запуск погодного пайплайна. Перед ETL ingestion должен успешно завершиться.
- SQL из `postgres/init/` исполняется только при первом создании PostgreSQL volume. Существующую схему обновляй адресно; не удаляй volume ради миграции.

## Команды проверки

Из корня репозитория в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для тестов Spark нужны зависимости из `processing/spark/requirements.txt` и Java 17+. Не запускай реальные ingestion или ETL для проверки документационных правок: они обращаются к внешним источникам и меняют MinIO/PostgreSQL.
